# Falcon-512 Verify Benchmark — Measured Report

> Generated by `cargo run --release --bin report`.
> Falcon-512 (NIST level 1, lattice/NTRU, FIPS 206 draft), one signature
> format, two implementations: fastcrypto's Montgomery-NTT verifier
> ([`pq-schemes`](https://github.com/mahdi-mysten/fastcrypto/tree/pq-schemes))
> and PQClean's portable C (`pqcrypto-falcon`). Both rows verify the
> identical signature bytes.
> Median of **1000 iterations** for verify (the PQShield-zoo method) and
> **100** for keygen/sign (off-chain context), warmup 2.
> Measurement host: **non-x86 (wall-clock ns; no rdtsc)**.
> Only **verify** runs on-chain; `sig` is per-tx calldata; `pk` is stored.

## 3. How to read this

- Both rows verify the same PQClean-generated signature bytes; the delta
  isolates implementation style alone (Rust with precomputed Montgomery
  tables vs PQClean's portable "clean" C behind FFI).
- Only the PQClean row has keygen/sign cells — the fastcrypto row is
  verify-only by design (signing carries Falcon's floating-point sampler
  and never runs on validators).
- Cycle medians (x86_64 rdtsc) are the unit the PQShield NIST-sig-zoo
  reports, so those numbers can be compared directly with the zoo.
- Neither core is independently audited; read the numbers as comparative
  evidence, not as a production benchmark.
